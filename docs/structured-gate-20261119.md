# PM-Bench v9 短输出与结构化证据对照

冻结第十一轮的 42 个配对，复用原有可见历史、原生菜单、通道、实际回包、原始读后动作 C 和无回包动作 B。既有的 B 与 C 动作集合相同的 10 对直接沿用 C。其余 32 对，两组各发一次 Qwen3.5-27B 请求，按配对交错请求先后。使用 `distill/utils.py` 原路由、相同种子、采样参数、256 输出 token 上限和动作执行器。没有新的环境读取。 [上一轮报告](action-gate-20261119.md)

- 短输出组保留上轮核验规则，输出仅为接受的增、删动作编号，不附理由。
- 结构化证据组采用同样短输出。模型在原输入上看到一个由当日可见任务指令、现有动作文字及最近两条逐字匹配的叙述构成的索引，结合上一条实际回包核对对象、属性、时间和最新指令。索引只摘录原文，保留找不到匹配的空字段。缺少条目发生时间时只能判未知。未提供金标事件 ID、隐藏时间、到期集合或评分结果。

两组的推理次数、环境读取次数和实际输出上限一致。索引会增加输入 token，实际输入消耗单独报告。解析失败沿用 C；未改变的共同动作不进入核验范围。评分重放到当前步，逐项检查误报、非到期动作、目标及其他到期待办。

## 冻结判据

沿用上一轮判据。相对 C 必须至少减少 3 次官方误报，非到期动作不增加，逐项保住 C 的 22 个目标命中和 30 个其他命中，并至少恢复 1 项 C 丢掉的 B 正确待办。判定结构化索引有额外收益还要求它自身过线、比短输出组至少少 1 次误报，并保住短输出组已命中的目标和其他待办。42 对均为已用过的开发诊断，不当作独立验证。择时暂停。

### 逐项核对

- 唯一改变正式待办集合的是短输出组的 `d3_s4:41`。模型不再新增已取消的会费，少 1 次官方误报。它仍选择迟到的哮喘待办，仍没保住实验室投递。结构化组在此例把拟新增的哮喘待办写进删除列表，按规则回退。索引的逐字匹配还漏掉了含「paying」的会费取消叙述。完整原始历史仍包含这段话。
- `d1_s10:19` 两组都把拟新增的还书动作列入删除，而非省略该新增项。`d6_s6:19/41` 的结构化索引摘出了发邮件的 11:50 新时间，两条输出均未接受新增邮件动作，但把同一编号写入删除列表。三例均触发了冻结的原动作回退。
- `d2_s2:19/67` 两组两次都保留同通道的错误改期动作。最新实际回包只报告换房间。`d4_s3:67` 两组保住配送目标，仍漏掉柜台取件。共同动作也不在增删核验范围内，例如 `d7_s7:41` 的实验室门户误报。

### 事后离线解析敏感性

两组所有解析失败都只涉及把某个拟新增、且未列入接受新增的编号写进了删除列表。对这些已保存输出，离线忽略越界删除项并保留其余决定，再用原生执行器重算。短输出组误报为 9，结构化组为 8，二者仍没有恢复任何丢失的正确待办。该诊断说明输出约定与回退掩盖了部分拒绝误报的信号，不能凭此把任一组判为通过。正式账本保留冻结的回退和得分。择时未重跑。
