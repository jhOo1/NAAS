# PM-Bench v9 共同通道策略与择时复验

2026-11-19。在第一次 Qwen 请求前冻结通道提示、覆盖门槛和择时协议。沿用 PM-Bench 官方 `synthetic_week_v9`，固定上游 `e1093c470c8981daf522d4ef047a7c3a71e077d7`。使用 `distill/utils.py` 的原 Qwen3.5-27B API 及已有原生执行器。 [官方 PM-Bench](https://github.com/genglinliu/PMBench) · [上轮非时钟回放](nonclock-replay-20261119.md)

## 覆盖审计

以同一合成周中上轮确定的 14 个决策窗、15 项非时钟待办为审计范围。三种子 19、41、67 共 42 个窗口配对。模型得到固定周期轨迹截至该决策步的可见历史、任务描述、原生事件和当步原生动作菜单，以及在更早事件步已经读到的回包。通过原归档提示哈希核对重建。移除该步归档原有的当前回包，使该步唯一一次读由待测通道策略决定。模型每次输出一个通道和无新回包时的动作。通道策略优先检查可见待办中有明确依赖的非时钟来源，当前叙述可用于排序，无合适来源时选择时钟。实际读取按原生工具行为，只向动作模型追加该唯一通道的完整回包，然后用同模板执行最终动作。

下列门槛全部通过才进入择时；审计窗口与种子固定，途中不调整通道提示。模型不可见目标索引、隐藏时间、金标通道、其他通道的实际状态、后续事件或门槛。金标仅在离线核对时使用。

| 通过项 | 冻结标准 |
| --- | --- |
| 审计范围 | 至少 10 个不重叠事件步 |
| 窗口覆盖 | 至少 8 个窗口在至少 2/3 的种子中收到任一当前目标线索 |
| 待办和通道覆盖 | 至少 5 个不同目标各有 2/3 种子匹配，覆盖至少 3 个非时钟通道 |
| 读到且执行 | 至少 8 次在原生回包中匹配当前目标并准时执行 |
| 其他到期待办 | 至少保留无读时已完成的 90%，按动作身份配对 |
| 误报 | 42 个窗口配对合计，读后官方误报至多比无读多 1 次 |

8/14 要求在多数已知机会中找到当前条目。任务及通道门槛用来排除收益全来自少数重复来源的情况。90% 保留和至多 1 次额外误报是这轮诊断允许的退化幅度。另报所有非到期动作和有回包但未执行的情况。时钟或其他回包只要没有同一步所需的源与事件条目，就不算本轮目标匹配。每个窗口只付一次读取成本，审计时点已知且来自已见的公开合成周。

## 条件择时复验

审计通过后，把 80 个共同可观察事件步划为上轮的九段。依时间先后，在每段首个事件步使用冻结策略为该段选一个真实通道。策略输入来自不读取工具、执行空待办的共同参考轨迹，含原生历史、截至该步的叙述和菜单。参考轨迹没有闭环两组的回包或未来叙述。九次通道和顺序在闭环开始前存入账本，通道分配的九次模型调用作为两组共同开销单报。

两组都在段内对该段锁定的通道判断是否现在需要读取，并产生无读时的临时动作。固定组在段中点读取，按需组在首次建议读取的事件步读取，段末兜底。原生回包按各自的读取时点生成，依各自的已读状态更新。使用同样的模型、输出预算、动作处理逻辑和配对种子。每组实际读取 9 次，读取通道和顺序严格相同。执行器如实保留闭环历史差异。

报告实际读取步、每个回包、当前线索匹配、是否准时执行及整组到期动作。官方整周 Set-F1、非时钟准时命中、其他到期待办、误报及 token 均报告。支持继续择时研究需要非时钟准时命中与 Set-F1 同时增加，并保住其他到期待办，不增加官方误报和非到期动作。届时只作单个公开合成周的证据。

## 复现

```sh
python3 run_pmbench_channel_lock.py /path/to/PMBench runs/pmbench-timing-20261119.json \
  --api-utils /path/to/distill/utils.py --output runs/pmbench-channel-lock-20261119.json

  --verify-only --output runs/pmbench-channel-lock-20261119.json
```

若请求中断，以同一路径加 `--resume` 可保留已成功的模型响应。
