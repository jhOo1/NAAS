# PM-Bench v9 非时钟待办三臂回放

2026-11-19。对象为正式九次读取对照中两组共同漏做、且均未读到匹配回包的 15 项非时钟待办。它们分布在 14 个决策步和 7 个通道。诊断用上一轮固定周期组作为唯一归档前缀，重建原生菜单、先前模型动作和先前及本步已返回的状态。保留第 5、22、58 和 76 步已获得的时钟回包。原输入组从同一前缀用共用动作提示重答，因此可能与归档正式动作不同。 [择时对照账本](../runs/pmbench-timing-20261119.json) · [官方 PM-Bench v9](https://github.com/genglinliu/PMBench)

每步每个种子独立做三臂。A 用原可见输入，B 追加目标通道的原生完整回包，C 追加无关的 `price_tracker` 原生回包。B 和 C 各增加一次读取，回包 token 长度随原生内容变化。所有当前关键条目均按通道及事件 ID 对上官方到期待办，无关回复有内容且不对应场景的待办通道。所有臂使用 `distill/utils.py` 的原 Qwen3.5-27B API、同一次最终动作请求、同一输出预算和同一执行器。配对种子为 19、41、67，逐步逐种子交错臂顺序。银行和图书馆两个目标同在 `d3_s9`，分别只补一个通道，两个目标复用同一组 A 与 C 请求。 [执行脚本](../run_pmbench_nonclock.py)

各臂不继承其他臂的动作。离线重建完整归档，校验原提示哈希、当前关键回包以及各臂实际送入的文本和提示哈希。对每个动作使用官方计分器复核截至该步的归档前缀，在该步与空待办动作相减，得到官方准时命中、误报和其他错误记录。另报所有非到期动作数，官方计分会将部分此类动作归为迟到或重复执行。严格净恢复要求同一配对中 A 和 C 都遗漏目标，B 完成目标，且保留任一对照完成的其他到期待办、无新增非到期动作及官方误报。

这里使用回放者已知的到期点和正确通道，估计当前动作模型在该前缀和一次额外读取下的可恢复空间。15 项来自同一个已看过结果的公开合成周，重复种子及共用窗口不构成独立周。本轮追加的读取按窗口独立计算。

### 对择时复验的含义

本轮结果足以支持测试一个能覆盖非时钟来源的共同通道策略。严格净恢复跨 6 个通道，完整集合明显改善，同时官方误报多 1 次、其他命中减少，因此下一轮仍需以整周准时行动、误报和证据覆盖共同判断。建议先冻结只依赖模型可见历史和待办描述的通道策略，用九次读取预算验收其非时钟覆盖。若要把差异尽量归于择时，两组可共用提前确定的各段通道，只在段内改变读取时点。本轮的正确通道与到期点由回放者提供，不能把 40 次命中作为整周九次策略可达的结果。

## 复现

```sh
python3 run_pmbench_nonclock.py /path/to/PMBench runs/pmbench-timing-20261119.json \
  --api-utils /path/to/distill/utils.py --output runs/pmbench-nonclock-20261119.json
python3 run_pmbench_nonclock.py /path/to/PMBench runs/pmbench-timing-20261119.json \
  --verify-only --output runs/pmbench-nonclock-20261119.json
```

可以先在新输出路径用 `--prepare-only` 核查 14 个窗口，然后加 `--resume` 调用模型。中断后对同一路径用 `--resume` 可复用已经确认的响应。
