# NAAS 第三轮 · 提示后的证据核验

2026-11-18。基线是本地 `255a5a3` 和 [NAAS 网页讨论](https://chatgpt.com/c/6afd60fd-dfc8-83ec-a099-939aeaa60eeb)。原生覆盖审计在 20 个公开任务、256 个冻结候选中找到 0 个严格满足多决策读取预算竞争的窗口。宽松上界 5 个窗口，原启动门槛是 10 个窗口、5 个任务。第三轮探索收到原生提示后的单决策取证。

## 研究问题

**长期个人助理收到更新线索后，能否在有限预算下读到足以改变当前行动的那条证据？** 例如，「返京航班状态需要复查」只触发核验。代理需要把日历中的待更新记录与具体航段和出行日期对齐，再确认该航段的当前登机口。历史行程可以提供检索键，当前状态要从当时可读的来源取得。

组合点来自主动诊断和长期代理。主动诊断为竞争行动选择能区分结果的测试。长期代理要处理旧记录、相似对象及异步更新。候选方法从初始可见历史提取当前待决动作及其分歧条件，以对象、时间和来源约束生成读取候选。检查读取的结果能否区分行动分支，并在后续操作前核对它是否覆盖正确对象和当前时点。无判别价值时保留原状或推迟行动，由各组共用的执行器处理。

首个可实现版本使用冻结模型提取 `对象 → 待决动作 → 分歧事实`，用同一份工具文档提供候选，记录候选的返回字段、对象约束、可用时间以及读取开销。按「能否确认分歧事实、何时可用、读取成本」排序。读取后只用本次实际返回及历史可见证据更新决策。版本和时间解析失败留作未判定，避免把工具返回时间等同于世界状态生效时间。先用人工选择的可读证据测诊断上限，再评估自动选择。

### 最近邻与论文边界

- **主动诊断和决策实验设计。** 决策损失驱动的读取选择已有正式框架。ACTMED 已用 LLM 配合贝叶斯实验设计迭代选择诊断测试。需要证明语言代理环境中的对象对齐和状态版本约束，在可验证行动上带来额外收益。 [Ji & Carin](https://doi.org/10.1016/j.patcog.2006.11.008) · [决策导向的贝叶斯实验设计](https://papers.nips.cc/paper_files/paper/2024/hash/c59f05d7ab3638b138cc61f32e1a7cd1-Abstract-Conference.html) · [ACTMED](https://papers.nips.cc/paper_files/paper/2025/hash/7c42e8a9eb471d225a4abec5e79d0153-Abstract-Conference.html)
- **LLM 工具取证。** 预算内按信息价值选搜索和决定何时提交已有近邻。主基线必须看到同样的全部上下文、对象和工具说明，可读任意允许来源、用缓存、主动等待，并明确提示它关注会改变行动的当前证据。 [Inference-Time Budget Control](https://arxiv.org/abs/2605.05701)
- **Proactive agent。** ProAct 会按相关性、知识缺口、增量价值和时效性做空闲采集。Pro-Memory 把待激活意图与观察纳入长期代理。SentinelBench 的 `wait_for` 支持差分和自适应刷新。初期只研究原生唤醒后的具体读取，使用共同的等待和缓存原语。 [ProAct](https://arxiv.org/html/2605.25971v1) · [Pro-Memory](https://arxiv.org/html/2611.05731v1) · [SentinelBench 附录 D](https://arxiv.org/html/2606.05342#A4)

论文主张暂悬。候选故事是「代理如何用一次读取把旧计划重新对齐到当前世界」。必须先证明存在可归因的漏读或读错，再比较方法对强基线的额外收益。

## 下一轮实验协议草案

### 先定位可修复失败

1. 先选原生开发窗口，要求提示没给出完整答案，关键记录当时可读，最终动作或持久状态可核验。已读事实、没有合法读法、评分只能判断写过关键词的例子不进入主机制样本。华东 S18 与租房 S10 用于验证记录与评分流程。Galápagos S19 做评分敏感性对照。三例均已暴露，后续独立检验按整任务留出。
2. 运行强全局规划基线并保存原生阶段快照、模型可见前缀、候选列表、实际工具参数及原始响应、最终操作和状态。纳入的失败需由原生或事先冻结的行为判据识别，并由完整轨迹确认关键读数缺失、取错对象或过期。对已经读到关键证据的失败单独记录执行环节。
3. 在同一决策点从相同快照重跑三臂。A 重跑原输入，不注入读数。B 在公共的工具消息槽注入原时点实际可得的关键工具返回。C 注入同工具类型、同成本、响应长度和延迟相近的真实无关返回。可在开发例另做同对象旧状态对照，判断对象匹配与时效的作用。A 的原轨迹分数用于确定失败，A 的重复运行用于测模型自然恢复。B、C 只补原始响应，使用统一语义和格式，保留原始工具字段，禁止研究者解释、未来状态、评分文本、正确操作提示和预写后端状态。若基线未发过读取，用固定入口追加同构工具消息。B、C 按增加的一次读取计费，后续读取预算等额且每臂只能看自己的响应。固定下游模型与设置，使用可复位快照和配对随机种子或重复试验。
4. 报告原生得分，并事先冻结两个可独立检查的指标。**证据到达**依据决策前实际工具结果中的对象、有效版本和值。**动作正确**依据最终状态或原始操作，与目标事实逐项匹配。盲审只看试验轨迹和同一规则。根因归因必须同时看到关键证据在决策前到达、正确动作恢复、并且无关对照没有恢复。原生分与严格指标的分歧单列。

此阶段的相关证据由评估侧挑选，给出决策点可修复性的诊断上限。B 和 C 的上下文成本、检索结果长度及延迟单列。A 与 B 的差异可能包含多一次读数的影响，B 与 C 用于排查只是多了一条工具消息的解释。

### 通过归因门槛后再比方法

- 主对照是同模型全局规划器，明确提示优先考虑对象一致且会改变决策的当前证据。两组共享初始历史、候选工具、读写权限、截止时间、缓存和等待。固定同一执行器，与只加入核验提醒的同提示对照并跑。主比较为自动选择对同提示全局规划，人工挑选只作上限。另用无结构的自由文本表达相同条件，检验提升究竟来自表示还是多给了一次推理机会。
- 在一读和两读预算分别比较，报告真实工具返回 token、调用数、模型开销和决策完成时延。预先冻结主判据为截止前完成且严格正确的动作率，并报告原生分、错误动作、旧状态传播。以独立任务作配对统计单元，对预算、模型和数据版本分开报告结果。
- 若开发样本缺少跨任务的可重现失败，关键证据不能稳定恢复、B 与 C 恢复相近，或大部分失败发生在证据已到达之后，就停止扩展方法。若相关证据能恢复但自动选择无法改善同预算强基线，保留失败归因结果并重新评估算法主张。
