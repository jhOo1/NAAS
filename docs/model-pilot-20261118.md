## 评分和决策

严格指标核对原始响应确实含有可归属到目标对象的当前事实，并核查最终记录中的对象、状态和动作字段。回放同时保留原生选定评分项，三组原生通过数同为 `0/9、9/9、0/9`。租房只调用 `s10_calendar_conflict_found`，它检查读到日历冲突，内部草案更新由本轮的严格动作判据核验。此前重放发现的原生评分漏洞仍适用。Galápagos 状态字段存在时区差异，此轮以变更派发顺序确认可读性。 [原生判据重放](evidence-replay.md#已验证的评分契约)

**裁决：先测自由选读强基线，暂缓实现自动选择器。** 本轮证明，在这三个已暴露的决策点上，给定正确工具返回足以让模型完成核验并执行精确更新。窗口是定向挑选的，历史是固定重建的，原输入无再读取机会。三次重复共享同一窗口，独立案例数是 3。模型能否主动找到关键记录，以及相同预算下强全局规划器究竟会错过多少次，仍需实测。下一关让同一模型从原生可用的同一候选范围自由选一次读，随后交给同一个执行器。按实际返回区分对象、时间、来源错误和拿到证据后的执行错误。若强基线已在这些窗口达到补证上限，开发集诊断到此为止，方法主张需要在独立且有可修复漏读的窗口重新验证。

## 复现

依赖 Python 3.9+、PyYAML、loguru，模型配置通过上述 `utils.py` 传入。输出包含公共提示、原生读数、每次模型原文、动作、最终记录、评分和用量。配置凭据仅用于请求。

```sh
python3 run_evidence_pilot.py /path/to/VibeLifeBench \
  --api-utils /path/to/distill/utils.py \
  --output runs/model-pilot-reproduction.json
```

数据快照可用 `--prepare-only` 检查。中途中断可在同一输出路径使用 `--resume`，已完成的请求会保留。
